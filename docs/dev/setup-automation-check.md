# 自动设置真机验收

入口：首次选择并启用本地或在线主模型后，点击「解锁高级功能」；若先前选择「稍后」，可随时从设置首页的「解锁高级手机操作」进入，也可从「设置 → 手机操作」顶部进入正常设置。随后点击「开始自动设置」。进入页面本身不会自动点击系统设置，普通解锁也不会触发「重新配对」。

首次无障碍授权由用户手动完成，随后优先以固定规则识别主屏系统设置的无障碍节点。打开「使用模型识别不同的设置菜单」后，规则无法确定目标时才请求当前主模型辅助判断。自动流程尝试依次打开开发者选项、USB 调试、无线调试与配对窗口；密码、系统确认框仍等待用户处理。系统限制读取设置页面时，提示用户返回 Mika，手动完成下方当前步骤后再点「开始自动设置」，已完成的步骤会跳过。已由 USB/root 启动且连接正常的手机助手在无障碍连接后直接视为就绪，不额外启用无线调试。开启开发者选项本身不等于已完成高级功能，最终以无障碍与手机助手均连接为准。

自动选择器目前覆盖简体中文、繁体中文和英文的常见设置标题。界面支持仓库现有的十种语言，不代表十种语言的系统设置都已适配。厂商界面需逐机验收。

## 模型辅助

模型辅助跟随「设置 → 模型」中已选用的主模型，不固定为任何模型品牌。本地主模型在手机内处理，在线主模型接收筛选后的设置菜单标题和可操作候选。开始按钮上方显示当前模型名和处理方式；有主模型时辅助开关默认开启，可在开始前关闭。开始时固定本次使用的模型，开关在会话运行期间不可修改。尚未配置主模型时，模型辅助开关不可用，固定规则和手动步骤仍可使用。

请求仅用于从当前候选中选择一个设置动作，不给模型任意执行工具的权限。设备详情、输入字段、密码和配对码不作为提示内容，也不发送截图。模型返回后，执行器仍须重新确认当前系统设置窗口与控件，动作执行后继续检查实际开关状态和助手连接。模型未给出有效动作、请求失败或设置页面不可读时，保留手动继续路径。

每次模型调用最多 45 秒、每次设置会话最多 10 次请求，相同候选页面复用已校验建议。版本入口最多点击 7 次，开启调试只尝试一次，菜单导航每步最多 5 次；不支持工具调用的主模型走原有规则回退。停止会取消进行中的模型调用，旧建议不能在新会话执行。

本次接入的是基于控件树的文本模型辅助，没有接入截图 OCR 或视觉模型。模型不会增加系统权限，也不代表所有手机型号均已适配。此前 MuMu 实测仍仅证明下面记录的规则与电脑启动路径，不能作为新模型路径的全机型验收证据。

## 验收场景

0. 全新安装先出现无障碍授权页，授权连接后进入模型配置；保存且选好主模型后只显示高级功能邀请。点「稍后」不打开系统调试页，再次启动不重复邀请；只有点击「解锁高级功能」才进入下面的自动设置。首次授权跳过、模型保存失败、只保存服务商未选主模型、账号登录提示未确认，也应分别保持正确的页面。
1. 未开启开发者选项：启动自动设置，手动开启 Mika 无障碍，确认自动打开关于手机、最多点击七次版本号；有锁屏凭据时必须等待手动输入。
2. 部分步骤已完成：分别预先开启开发者选项、USB 调试、无线调试，确认跳过已有设置，不把开关关闭。
3. 系统确认：USB 调试确认、无线调试网络授权、厂商自定义确认框出现时不自动确认；完成后继续，取消后不重复点开关。
4. 无 Wi-Fi：无线调试无法开启时退出到手动流程，不修改 Wi-Fi 配置、不盲点其它开发者选项。
5. 配对：打开「使用配对码配对设备」，已有读码逻辑完成配对和连接；配对码不进入日志、状态条或文档。
6. 用户切换 App、打开通知栏或锁屏：暂停点击，绝不点击背后的设置。返回可识别设置页且仍在会话时继续。
7. 随时停止：状态条和 Mika 引导页均可停止；手动操作入口也先停止。停止后立即重新开始，旧协程不得关闭新会话的浮层或配对观察。已开始的握手允许完成。
8. 兼容性回退：无障碍被暂停、存在重复标题、节点不完整、设置标题未支持、开关状态读不到时交回手动。重启 App 不自动恢复会话。
9. 时限：单步 90 秒、整次 5 分钟，超时后没有继续点击，返回 Mika 可看到提示并重试。
10. 跳过首次邀请后，设置首页的「解锁高级手机操作」能进入正常向导；没有主模型时也能设置。已就绪隐藏重复解锁入口；手机操作页显示已启用状态。已运行的 USB/root 助手不为普通解锁再次启用无线调试。
11. MuMu 的简体中文「关于本机」页面使用「Build 号」：应能识别并点击该行；外层 `ScrollView` 包住 `RecyclerView` 时选择唯一最内层列表，并列滚动区域仍交回手动。页面上的「正常运行时间」刷新时只重新取树，不消耗点击次数或结束会话。
12. 设置页存在未聚焦的标准搜索框时仍能识别目标；搜索框聚焦、密码框或系统确认出现时暂停。仅在无障碍描述中提供标题的节点也须精确匹配，重复标题仍交回手动。
13. 系统保护设置页面、普通无障碍服务持续读不到节点：明确提示该页受系统限制，结束自动操作并保留手动步骤；手动完成后重新开始，跳过已完成的开关，不把页面不可读误报成等待用户确认。
14. 模型辅助关闭或尚未配主模型时，不调用模型，固定规则仍可工作。当前主模型为本地/在线时，开关附近分别显示本机处理/向所配置服务发送菜单标题的说明。
15. 固定规则不识别、但有可读的设置候选时才调用主模型。返回不存在的候选、确认按钮、已开启的开关或不适用的动作时不得执行；请求期间换窗口、出现确认框或点击停止后，也不得执行旧推荐。
16. 模型辅助运行期间不能切换开关；停止按钮始终可用。失败时能够返回手动步骤，重新尝试时跳过已完成的开关。不同厂商、语言和模型均需单独验收。

## MuMu Android 15 实测记录

2026-11-10，在当前 MuMu Android 15 镜像上复现并验证：修复嵌套滚动容器和「Build 号」标题识别后，Mika 自动滚动三次、点击版本入口七次，系统的开发者选项从关闭变为开启。

进入开发者选项后，该镜像将页面节点标记为敏感内容。调试探针能够读到页面的 42 个节点，而 Mika 的普通无障碍服务持续拿不到页面根节点；改为从当前活动窗口获取根节点后仍然如此。因此，本次没有完成 USB 调试、无线调试及配对的全自动验收，不能将开发者选项开启成功当作整个高级设置流程已通过。

在此镜像上，用户需手动开启 USB 调试和无线调试、完成系统确认；配对页面若同样受限，则按向导手动配对，或改用「用电脑启动」路径。完成后返回 Mika，可再次开始自动设置以跳过已完成步骤。此结论仅针对本次 MuMu 镜像，不代表所有 Android 15 手机都限制相同页面。

最终修复包实测：相同受限窗口约 4.2 秒后报告 `PageUnavailable`，返回 Mika 可看到明确提示。手动开启 USB 调试并确认后，通过应用自带的 `usb-start.sh` 启动助手，向导显示「手机操作已经设置好了」。这是电脑启动路径通过，未启用无线调试、未完成无线配对。

最终自动设置专项回归共 27 项通过，10 种 UI 语言的 2293 项资源检查通过，APK 签名校验通过。安装包为本地 `dist/Mika-auto-setup-mumu-fix-debug.apk`（123421813 字节），SHA-256：`49819f0d36cc4c4259cab5aaa6d82f93cc4f9c3e8b5cb3b903b1cc3240898d33`。APK 不随源码提交。

## 排查自动设置暂停

通过 `adb logcat -s MikaSetup` 查看阶段、点击/滚动结果及分类原因。`Retry/SnapshotChanged` 表示尚未下发动作、下一轮重新识别；`Failed/ActionRejected` 表示系统拒绝了实际动作，流程停止。`PageUnavailable` 表示同一活动窗口持续 4 秒没有返回根节点，显示手动继续提示，避免空等单步超时。日志不包含页面文字、密码或配对码。

`SetupAutomationActionTest` 覆盖运行时间刷新、复用的设置行、确认框及窗口变更，防止将旧节点误点到新控件上；`SetupAutomationTreeTest` 包含「Build 号」、嵌套滚动、搜索框和内容描述的回归案例。`SetupAutomationAvailabilityTest` 验证窗口加载宽限期及切换/恢复可读页面后重新计时。

## 本地检查

需要 JDK 17、Android SDK 36 和 Build Tools 35.0.0。Windows 上应从纯英文路径构建；项目现有的 `protoc` 工具无法正确读取中文路径，可将项目映射到临时盘符后运行。

```text
gradlew.bat :app:compileDebugKotlin
gradlew.bat :app:testDebugUnitTest --tests "*OnboardingTest*" --tests "*ModelSetupViewModelTest*" --tests "*SetupAutomation*" --tests "*SetupModel*" --tests "*PhoneSetupCopyTest*" --tests "*StringResourcesTest*"
gradlew.bat :app:assembleDebug :app:compileDebugAndroidTestKotlin
python tools/i18n/translations.py check
```

`OnboardingTest` 验证首次路径和跳过后的恢复；`ModelSetupViewModelTest` 验证保存完成后才推进。`SetupAutomationTreeTest` 验证选择范围、已开启的开关、重复/相邻设置行、确认框/密码和未知窗口的拒绝行为。`OnboardingPermissionScreensTest`、`SetupAutomationScreenTest` 验证显式授权、解锁与停止入口；需要连接设备才能运行。JVM 与编译检查不能替代上述真机验收。
