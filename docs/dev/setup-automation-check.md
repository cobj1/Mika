# 自动设置真机验收

入口：首次选择并启用本地或在线主模型后，点击「解锁高级功能」；若先前选择「稍后」，可随时从设置首页的「解锁高级手机操作」进入，也可从「设置 → 手机操作」顶部进入正常设置。随后点击「开始自动设置」。进入页面本身不会自动点击系统设置，普通解锁也不会触发「重新配对」。

首次无障碍授权由用户手动完成，随后优先以固定规则识别主屏系统设置的无障碍节点。打开「使用模型识别不同的设置菜单」后，规则无法确定目标时才请求当前主模型辅助判断。自动流程尝试依次打开开发者选项、USB 调试、无线调试与配对窗口；密码、系统确认框仍等待用户处理。USB 调试页面控件不可读时，尝试下文说明的本地截图 OCR；其他不可读页面、截图失败或无法可靠定位时，提示用户返回 Mika，手动完成下方当前步骤后再点「开始自动设置」，已完成的步骤会跳过。已由 USB/root 启动且连接正常的手机助手在无障碍连接后直接视为就绪，不额外启用无线调试。开启开发者选项本身不等于已完成高级功能，最终以无障碍与手机助手均连接为准。

自动选择器目前覆盖简体中文、繁体中文和英文的常见设置标题。界面支持仓库现有的十种语言，不代表十种语言的系统设置都已适配。厂商界面需逐机验收。

## 模型辅助

模型辅助跟随「设置 → 模型」中已选用的主模型，不固定为任何模型品牌。本地主模型在手机内处理，在线主模型接收筛选后的设置菜单标题和可操作候选。开始按钮上方显示当前模型名和处理方式；有主模型时辅助开关默认开启，可在开始前关闭。开始时固定本次使用的模型，开关在会话运行期间不可修改。尚未配置主模型时，模型辅助开关不可用，固定规则和手动步骤仍可使用。

请求仅用于从当前候选中选择一个设置动作，不给模型任意执行工具的权限。设备详情、输入字段、密码和配对码不作为提示内容，也不发送截图。模型返回后，执行器仍须重新确认当前系统设置窗口与控件，动作执行后继续检查实际开关状态和助手连接。模型未给出有效动作、请求失败或设置页面不可读时，保留手动继续路径。

每次模型调用最多 45 秒、每次设置会话最多 10 次请求，相同候选页面复用已校验建议。版本入口最多点击 7 次，开启调试只尝试一次，菜单导航每步最多 5 次；不支持工具调用的主模型走原有规则回退。停止会取消进行中的模型调用，旧建议不能在新会话执行。

主模型辅助仍只分析控件树中的菜单标题，不接收截图。USB 调试另有内置 OCR 专用回退，不调用所配置的在线或端侧主模型。模型不会增加系统权限，也不代表所有手机型号均已适配；下面的历史验收仅证明各记录所列的路径。

## USB 调试的本地画面识别

在 USB 调试阶段，系统设置的控件树不可读，或只隐藏敏感的 USB 行但仍允许普通无障碍服务截图时，使用应用内置的中英文 OCR 识别画面。开始按钮上方明确说明此回退：截图只在本机处理，不上传、不进入主模型请求，也不保存到文件或日志。这项固定规则回退不依赖主模型辅助开关。

执行器只在本次明确打开系统设置后、处于开发者选项列表、USB 调试仍关闭时尝试。系统提供包名时须与设置应用匹配；敏感窗口连包名也隐藏时，仅在启动后 15 秒内绑定一个标题精确匹配的开发者窗口，绑定最多保留本步骤的 90 秒，不能重新绑定到其他未知窗口。画面还须同时包含顶部开发者选项标题、总开关标题，以及可识别的设置列表或紧邻 USB 行上方的「调试」分组。找到唯一完整的「USB 调试」标题后，只点击标题本身；「USB 调试（安全设置）」等相似项目不作为目标。未找到目标时，仅在明确的开发者设置列表上有限滚动。

每次动作须由两帧稳定的识别结果支持，并在真正下发前重新核对窗口、锁屏和开关状态。切换应用、窗口变化、遮挡、目标裁切、重复标题、确认按钮或身份验证内容都会停止该次操作。USB 开关在一次会话中最多尝试点击一次，出现「允许 USB 调试」等系统确认时仍由用户完成；点击成功不等于开关开启，须继续检查系统实际状态。用户停止后不再发送手势。

Android 14 及以上使用普通无障碍服务的公开窗口截图接口，避开状态条和其他无障碍浮层；截图像素尺寸必须与已验证窗口的屏幕边界一致，点击坐标再加窗口偏移。Android 11–13 采集整屏截图时暂时隐藏本次自动设置状态条的内容，采集返回后立即恢复，再进行 OCR。两次识别与第三帧像素复核使用相同的采集方式。识别期间仍可点击停止，真正下发手势前也会拒绝被浮层遮挡的目标。设备点击测试必须携带真实状态条，不能只用无浮层的测试结果代替正常入口验收。窗口截图用途见 [Android 官方接口说明](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))。

本回退只定位 USB 调试开关，不自动识别或操作无线调试、配对码、密码及确认按钮。控件不可读不必然意味着禁止截图；系统禁止截图时不尝试绕过，交回手动步骤。该实现需要分别验收每个系统版本和厂商布局，不能把单台 MuMu 的结果推广到所有手机。

MuMu 窗口截图的内置 OCR 曾把非操作标题「开发者选项」识别成「开发老选项」或「开发考选项」，规则只接受这两种已观察到的标题误差；总开关与 USB 目标仍须精确匹配。截图对照诊断须额外显式传入 `verifySetupUsbCaptureComparisons=true`，仅测试 APK 会保存三种采集结果及输出固定标题区文字；正常应用及默认点击验收不保存图片、不输出页面内容。

## 验收场景

0. 全新安装先出现无障碍授权页，授权连接后进入模型配置；保存且选好主模型后只显示高级功能邀请。点「稍后」不打开系统调试页，再次启动不重复邀请；只有点击「解锁高级功能」才进入下面的自动设置。首次授权跳过、模型保存失败、只保存服务商未选主模型、账号登录提示未确认，也应分别保持正确的页面。
1. 未开启开发者选项：启动自动设置，手动开启 Mika 无障碍，确认自动打开关于手机、最多点击七次版本号；有锁屏凭据时必须等待手动输入。
2. 部分步骤已完成：分别预先开启开发者选项、USB 调试、无线调试，确认跳过已有设置，不把开关关闭。
3. 系统确认：USB 调试确认、无线调试网络授权、厂商自定义确认框出现时不自动确认；完成后继续，取消后不重复点开关。
4. 无 Wi-Fi：无线调试无法开启时退出到手动流程，不修改 Wi-Fi 配置、不盲点其它开发者选项。
5. 配对：打开「使用配对码配对设备」，已有读码逻辑完成配对和连接；配对码不进入日志、状态条或文档。
6. 用户切换 App、打开通知栏或锁屏：暂停点击，绝不点击背后的设置。返回可识别设置页且仍在会话时继续。
7. 随时停止：状态条和 Mika 引导页均可停止；手动操作入口也先停止。停止后立即重新开始，旧协程不得关闭新会话的浮层或配对观察。已开始的握手允许完成。
8. 兼容性回退：无障碍被暂停、存在重复标题、节点不完整、设置标题未支持、开关状态读不到时交回手动。重启 App 不自动恢复会话。
9. 时限：单步 90 秒、整次 5 分钟，超时后没有继续点击，返回 Mika 可看到提示并重试。
10. 跳过首次邀请后，设置首页的「解锁高级手机操作」能进入正常向导；没有主模型时也能设置。已就绪隐藏重复解锁入口；手机操作页显示已启用状态。已运行的 USB/root 助手不为普通解锁再次启用无线调试。
11. MuMu 的简体中文「关于本机」页面使用「Build 号」：应能识别并点击该行；外层 `ScrollView` 包住 `RecyclerView` 时选择唯一最内层列表，并列滚动区域仍交回手动。页面上的「正常运行时间」刷新时只重新取树，不消耗点击次数或结束会话。
12. 设置页存在未聚焦的标准搜索框时仍能识别目标；搜索框聚焦、密码框或系统确认出现时暂停。仅在无障碍描述中提供标题的节点也须精确匹配，重复标题仍交回手动。
13. 系统保护设置页面、普通无障碍服务持续读不到节点：USB 调试阶段仅在能确认窗口且允许截图时尝试专用 OCR 回退；其余情况明确提示手动继续。手动完成后重新开始，跳过已完成的开关，不把页面不可读误报成等待用户确认。
14. 模型辅助关闭或尚未配主模型时，不调用模型，固定规则仍可工作。当前主模型为本地/在线时，开关附近分别显示本机处理/向所配置服务发送菜单标题的说明。
15. 固定规则不识别、但有可读的设置候选时才调用主模型。返回不存在的候选、确认按钮、已开启的开关或不适用的动作时不得执行；请求期间换窗口、出现确认框或点击停止后，也不得执行旧推荐。
16. 模型辅助运行期间不能切换开关；停止按钮始终可用。失败时能够返回手动步骤，重新尝试时跳过已完成的开关。不同厂商、语言和模型均需单独验收。

17. USB 页面控件不可读但允许截图：主模型辅助开关打开和关闭时均能使用本地 OCR；网络请求中不得出现截图或完整 OCR 页面文本。只允许精确的 USB 调试标题，不点击相似的安全设置项。
18. 两帧期间滚动、转屏、锁屏、切换应用或出现确认框：旧坐标不得执行。其他无障碍服务的浮层覆盖目标时同样不得点击；模型和 OCR 均不确认系统授权。
19. USB 已开启则完全跳过，不反向关闭；关闭时仅点一次，用户取消确认后不重复点。USB 调试标题完整显示在页面底部时可以定位，裁切或重名则交回手动。
20. 截图被系统拒绝、OCR 失败、没有明确开发者列表、停止后立刻重开：保留手动路径，旧截图与旧会话不得在新会话中下发动作。

## 排查自动设置暂停

通过 `adb logcat -s MikaSetup` 查看阶段、点击/滚动结果及分类原因。`Retry/SnapshotChanged` 表示尚未下发动作、下一轮重新识别；`Failed/ActionRejected` 表示系统拒绝了实际动作，流程停止。`PageUnavailable` 表示同一活动窗口持续没有返回根节点，且当前阶段没有可用的专用回退，显示手动继续提示，避免空等单步超时。USB 本地画面识别须与一般的控件树读取日志区分；OCR 尝试与点击下发均不能当作开关已开启。日志不包含页面文字、密码或配对码。

`SetupAutomationActionTest` 覆盖运行时间刷新、复用的设置行、确认框及窗口变更，防止将旧节点误点到新控件上；`SetupAutomationTreeTest` 包含「Build 号」、嵌套滚动、搜索框和内容描述的回归案例。`SetupAutomationAvailabilityTest` 验证窗口加载宽限期及切换/恢复可读页面后重新计时。`SetupAutomationUsbOcrTest` 验证 USB 专用画面规则、两帧稳定性、相似标题、确认框与裁切拒绝；纯规则测试不能替代普通无障碍服务的实际截图、手势与系统状态验收。
