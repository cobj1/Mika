# 虚拟屏增强与模型开销

参考 [Agent-VScreen](https://github.com/kilolonion/agent-vscreen/tree/7e2e01491797848a82bb8bfe611842fb87fb9d10) 的持续触摸、画面观察和重接设计，使用 Mika 现有 Binder、任务隔离、访问策略与工具执行入口实现。参考仓库许可证为 MIT；本次未引入其服务或源码依赖。

## 持续多指输入

新增 `phone_touch`，支持 `down`、`move`、`up`、`cancel`，最多十根手指（`pointerId` 为 0–9）。除取消外，坐标使用当前屏幕的 0–999 归一化坐标。跨调用维持同一手势的 `downTime`；多指增减使用正确的 pointer action index。

`cancel` 取消当前任务所有手指，不会补发可能触发点击的 `up`。无输入 30 秒、显示方向改变、屏被释放、连接中断时取消；任务暂停、用户接管和普通手势开始前也清理。投递成功只代表输入已发送，不能宣称游戏动作、提交或其他业务结果成功。完整的短路径仍适合 `phone_gesture`。

## 连续观察

新增 `phone_watch`，仅在主模型能看图时提供。默认观察 3 秒，每 500 毫秒采样，最多返回四张变化帧；参数上限为 10 秒、八张、图片总计 4 MiB。每张图长边最多 640 像素，返回相对采样时间、原始生产者时间戳和尺寸。

采样按调用开始时刻的绝对时间槽调度，慢取帧跳过错过的槽位，不密集补拍；到截止时刻不再开始新截图或 PNG 编码。`sampledAtMs` 标记取帧开始，避免把编码耗时记成观察时间。已经进入的同步取帧或编码不能硬抢占，`elapsedMs` 保留实际耗时。

同一生产者帧不重新取样；先将新帧缩到长边最多 640 并取亮度格子，再与本次观察中最后保留的帧比较。近似相同的画面在 PNG 编码前丢弃，避免重复压缩、压缩缓冲区和 PNG 字节数组分配；未保留帧也更新生产者时间游标。缓慢积累的变化仍与最后保留帧比较，避免逐帧漂移被忽略；尺寸变化或取不到格子时保守编码。去重状态仅保存在这一次调用，缩略位图在筛选、编码、取消和异常的所有路径立即回收。

该工具只在调用期间取样，不持续录屏，不自动运行 OCR 或 Jev。每次读取经过应用访问边界，跳过编码时也保留读取后的访问复核；黑图和不可用帧不会当作成功。采样可能漏掉短暂变化，“没变化”不能证明成功或卡死；按旧图执行坐标动作前需要重新观察。

UI 预览现在由聊天小窗、后台屏展开卡片及悬浮胶囊共同持有可见租约：全部关闭或页面进入后台时，停止生成 UI 缩略图；显示时最多 5 帧/秒，限速区间内的最后一帧会延后发布。内部原帧继续最多 10 帧/秒更新，黑帧、变化格子和截图直接从这份新鲜原帧取样，且每种分析在同帧内缓存；不受 UI 预览开关影响。已有 Bitmap 消费者可能保留最后画面，发布过的 UI Bitmap 继续交由 GC 管理，避免提前回收。

可见需求同时管理网页预览：没有消费者时不再每半秒复制网页图片，网页前台时停止生成手机预览。手机与网页切换后主动恢复当前预览，静态手机画面无需等待新帧。发布前核对当前页面、标签及请求代次，迟到网页截图或较旧的权限检查不能覆盖新状态。后台屏和胶囊收到撤销帧时立即清图，取消待发布旧帧并重置去重；恢复同一张静态图也能再次显示。聊天完成态短暂保留最后画面的既有行为不变。

`phone_touch` 的执行体只查询当前窗口存在性及几何来换算坐标，省去额外的节点遍历与树哈希；`down`、`move`、`up` 仍分别经过风险门的实时读屏与不可逆操作判断，应用访问边界和副屏注入守卫保持有效。

## 异常退出后的接回

见 [虚拟屏恢复](virtual-display-recovery.md)。恢复条件是助手进程存活、两分钟内、同一会话再次发起任务。正常结束、用户停止以及超时均释放；不自动继续旧任务，不能跨助手重启恢复已经销毁的 Android 屏。

## 模型优化

本次已做：连续观察的绝对时刻采样、缩图和编码前变化去重；隐藏预览停止 UI 缩图；持续触摸省去执行体额外遍历；Jev 下载后最终路径单次 SHA、解码前评分缓存、统一加载预算、多行文本错误归因、下载前资源检查及 OCR 候选辅助裁剪，见 [Jev 说明](jev.md)。新增 [任务内按需校验](jev-task-verification.md)，普通读屏不加载 Jev，疑难或关键文字可单独调用。模型权重与评分含义保持原样；观察去重仍需复制缩略图和采样亮度栅格，减少的是未变化帧的 PNG 压缩和输出缓冲。

下一阶段按实际机型测试后再决定：

1. 在目标任务上评估按需文字校验的使用频率、耗时和纠错收益，避免主模型对每次普通读屏重复调用 Jev。
2. 已有手动裁剪后，比较不同分辨率与图像 token 预算的准确率；不能只以速度选参数。
3. 测量冷启动时间、单次评分时间、峰值内存、连续运行温度和耗电，再评估短时复用模型。当前仍在每次评分后卸载。
4. 建立中英文小字、模糊截图和常见 UI 字体的验证集，校准当前 Android 文本渲染带来的分数偏差。Jev 分数不能直接当任务完成概率。
5. 使用目标手机实测比较线程数、量化精度以及推理后端；没有同机结果前不承诺 FPS、延迟或提速比例。
