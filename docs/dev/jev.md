# Jev 本机文字校验

入口：设置 → 文字识别校验。下载前检查 ARM64 运行时、当前至少 3 GiB 可用内存、剩余下载空间及 128 MiB 存储余量；不满足时可整理资源后重新检查。通过仅表示初步资源满足，不保证推理速度或兼容性。下载约 1.95 GB 后选择图片，用左右、上下边界框出**单行或单段文字**。可点击「从所选区域识别文字」，选择候选自动填入文字并收紧裁剪框，也可手动输入。区域放大预览帮助确认选择；点击「在本机校验」获得未校准分数。

## 本次接入范围

- arm64-v8a、Android 11 起，实际需足够的可用内存。启动前检测低内存状态及至少 3 GiB 可用内存，这是保守准入值，不是经过真机验证的最低要求。
- 原生 llama.cpp CPU 程序随 APK 打包，固定版本、静态依赖、16 KiB 对齐，重建见 `tools/jev/build-android.ps1`。数据仅发给 `127.0.0.1` 随机端口且每次使用随机密钥。
- 模型只在页面明确评分或任务明确调用文字校验工具时加载；结束、失败或取消后退出。离开页面只取消页面操作，不取消独立任务的校验。父 App 退出时，原生入口通过 Linux parent-death signal 终止子进程。
- 下载支持断点续传、空间检查、明确停止和删除。完整字节下载后先建立 `.unverified` 标记、原子改名，再在最终路径核对一次 SHA-256，成功才清除标记。标记只是拒绝就绪的状态，不能替代 SHA。取消后保留待校验文件，下次继续核对；失败文件删除。推理前仍检查校验状态与文件身份，缺少可靠 stat 时回退完整 SHA。下载进度按 200 毫秒节流并始终发布阶段终值。
- 手动页面通过系统选择器获得图片，限制输入文件 8 MiB，原图区域输出最长边 1024 像素；候选文本 1～1000 字。任务工具只取得指定文字区域的同帧快照。使用 Android 系统字体渲染候选文本，**字体和预处理与官方 Chromium 参考环境不同，当前分数未经场景校准**。表格、公式和按分数自动授权动作不在本次范围内。
- 页面对上次结果绑定输入；修改图片或文字后隐藏旧评分。错误、超时、缺字段、越界概率不会当成 0 分。

## 校验与资源优化

第一次使用两份已存在的权重时，完整读取约 1.95 GB 并核对固定 SHA-256。同一 `JevModelFiles` 实例在本进程内缓存成功结果，后续打开页面或评分只比较 Unix 文件的设备号、inode、长度、mtime 和 ctime；任意字段变化会重新计算 SHA。mtime 被还原的同长度改写仍会因为 ctime 改变而失效，路径被替换则由 inode 区分。SHA 读取前后也比较文件快照，读取期间发生变化不会被认定通过。

下载和删除入口显式清空缓存，失败与取消不会缓存当前文件的校验结果。缓存不写磁盘，App 进程重启后重新完整校验；文件系统不提供 Unix 身份或 ctime 时，每次回退为完整 SHA 校验。缓存仅适用于本模块管理的应用私有文件。

实际推理仍独立加载并卸载原生模型，不增加后台常驻。结束时关闭原生进程的管道、HTTP 连接池和 HTTP 调度线程池；图片读取、解码和编码阶段之间检查取消，推理用 Bitmap 在取消或异常时释放。单次系统图片解码/PNG 编码调用本身不支持中途取消，内容提供方阻塞读取时也可能延迟退出。

### 重复评分复用

同一页面内，成功分数最多保留四项、五分钟，命中不延长期限。键由模型固定版本、预处理版本、原始文本、不可变源图片的内容摘要、裁剪框浮点位模式及当前 Android 渲染配置组成。源图片拥有私有字节副本，外部改写输入数组不会改变它。只保存摘要和分数，不保存图片或文字明文，不写磁盘。图片文件名或 URI 相同不代表相同输入。命中前仍验证权重，失败、取消及不在 0～1 的值不缓存；停止、离页、下载、删除或权重校验失败时清空。

命中时显示复用提示，不再次启动模型，也不要求加载模型的 3 GiB 可用内存。源内容摘要只在创建快照时计算；缓存检查前移到解码、文字渲染和 PNG 编码之前，命中可跳过整个预处理。仍需核对权重状态与组装请求键，不把命中描述为零开销。

## 任务按需校验

新增 `phone_verify_text(region, text?)`，普通 OCR 仍使用现有快速路径。主模型仅在普通读屏不足或关键字段需要复核时按需调用；不会为每次读屏加载 Jev，也不会自动下载模型。可指定紧贴文字的 0～999 区域及候选文字；省略文字时，在同一帧的同一裁剪图上运行本地 OCR，只有唯一候选才评分，多候选返回待选列表。

工具返回候选、区域、生产者时间戳、是否出现新帧及未校准分数，不设置通过阈值、不授权动作、不当作任务成功概率。读取前后都经过应用访问策略；任务取消传播到原生进程。页面、下载、删除和任务使用同一互斥入口，忙时立即返回，不同时加载两份权重。任务评分不跨请求缓存，页面离开不会取消独立任务。完整行为见 [任务内按需文字校验](jev-task-verification.md)。

任务路径在截图和 OCR 前检查可用内存，OCR 后再次检查，避免已知资源不足时仍扫描权重。通过校验时同步设置页的模型就绪状态；下载和删除完成后重新评估资源。任务截图直接从原始帧生成长边至多 1024 的文字选区，省去整屏 Bitmap 中间副本，四种旋转共用同一像素变换。选区按像素向外取整后，OCR 候选坐标依据实际区域映回。

本地 OCR 的两套识别器使用同一个输入图，全部已启动的识别器结束后才回收。初始化、结果转换及同步启动失败均完成资源收尾；取消后停止整理候选，但仍等待已经启动的识别器结束。普通单套失败继续允许另一套结果，内存分配失败会向调用方报告，不伪装成空文字。

端口等待、健康检查和模型身份检查共享 180 秒加载预算，健康/身份单次请求上限 5 秒；评分上限 180 秒。任务工具另有 7 分钟整体预算，外部任务取消仍优先。同步系统启动/解码调用只能返回后响应取消。多行文字先验证排版高度，超过范围给出文字错误，避免误报坏图。

### 文字区域与耗时

图片读取一次形成最多 8 MiB 的页面内快照，640 像素预览和后续评分共用该快照，避免相同 URI 的内容变化导致框选与推理错配。裁剪框用归一化坐标，先按原图文字区域计算缩放，不能先把整张长截图压成 1024 再裁小字。整图解码目标仍限制长边 4096、总像素 4 Mi 像素，区域输出最长边 1024，不放大小图；极长截图的小区域可能受整图限制而损失细节，可以先在系统相册裁成较小图片再导入。

`ImageDecoder.setCrop` 只保证裁剪输出，不能宣称只解码所选区域或保证真实峰值内存，见 [Android ImageDecoder 文档](https://developer.android.com/reference/android/graphics/ImageDecoder#setCrop(android.graphics.Rect))。推理临时 Bitmap 显式回收；交给 Compose 绘制的有界缩略图由 GC 回收，避免绘制尚未结束时回收位图。

页面将评分绑定到图片快照、裁剪框和文字；修改其中任意一项立即隐藏旧分数。实际推理结束后分别显示单调时钟测得的加载、评分秒数：加载包含原生启动、健康检查和模型身份核对；评分包含请求和响应解析。二者不包含图片预处理、权重校验、请求构造和进程退出。缓存命中只显示复用提示，不冒充新的推理计时。

下一步应先在目标机型记录冷启动/再次评分的加载耗时、评分耗时、峰值内存和热降频，再决定线程数、图像 token 预算或投影层量化。降低图像分辨率、token 数或量化精度需要同时复测中文、小字和易混淆 OCR 候选的评分区分能力，不能用未经测量的参数更改承诺提速或保持质量。当前继续使用固定 Q4_K_M 主模型与 F16 投影层，评分仍是未校准的一致性指标。

## 原生协议

`app/jev/JevProtocol.kt` 对应固定 llama.cpp 的 `/v1/systemone` 分类端点。`state` 是原样 OCR 文本，`images` 恰好两张：原图区域、候选文字渲染图；`questions.ocr.type` 固定为 `noul`。响应 `answers.ocr.noul` 必须是有限的 0～1 数值。

Jev 不是生成式聊天模型，不能调用聊天补全接口。官方 SDK 的 `/v1/score` 是额外 Python 服务的接口，本次直接使用原生评分入口，手机上不安装 Python/Chromium。

官方参考：[模型卡](https://huggingface.co/openbmb/MiniCPM-OCR-Jev)、[llama.cpp 部署](https://github.com/OpenBMB/MiniCPM-OCR/blob/main/docs/llamacpp_deploy_jev_en.md)。
